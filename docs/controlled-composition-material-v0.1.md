# Controlled composition: RC4 exact supplied RNA pair

RC4 constructs and independently checks complete artificial two-member RNA
material under the RC3 original-authority profile. This is a structural stage.
Reversible activity, source-to-mechanism behavior, joined therapeutic export and
research-project reopen remain later roadmap stages. The artificial MA/MG
fixtures are software controls, not usable CAR sequences or biological evidence.

## Authority and construction

The immutable v0.14 request retains the complete source, definitions, project
sources, activity model, operating domain, template roots, molecular expectations,
catalog binding, product/ORF/member mapping, context, resources and budgets.
The existing constructor reads the supplied material template and proposes the
ordered pair. The new closed candidate contains only `schema_version`, the full
`request_fingerprint`, and source-neutral `construction` content. Candidate
parsing confers no acceptance. RC3 inputs and their budgets are unchanged.

No behavior/implementation token is invented to enter an older material route.
The existing full component-material operations keep their meanings. The new
capability `policy_controlled_composition_material` exposes separate operations:

| Operation | Executable | Result |
| --- | --- | --- |
| `construct-policy-controlled-material` | Core | Untrusted proposal plus fresh structural assessment |
| `check-policy-controlled-material` | Core, Verify | Fresh independent assessment of original request and candidate |
| `publish-policy-controlled-material` | Core, Verify | Fresh assessment and, only if accepted, complete pair artifact |

All results use `policy-controlled-composition-material-v0.1`. Verify contains no
construction route. Neither construction nor checking publishes an artifact.

## Independent material checking

The new checker reparses complete originals, freshly runs RC3 admission, and
calls the existing independent mRNA structural checker. That checker privately
reconstructs expected content from independent template roots; it never imports
the producer. Every nucleotide, assembly correspondence, RNA region, ordinary
CDS translation, full protein identity, topology, cap/end chemistry, represented
tail and delivered-member order remains authoritative. Actual member and total
RNA lengths must satisfy the supplied resource ceilings.

Candidate-local hashes or an imported PASS do not replace originals. Changes to
UTRs, synonymous CDSs, chemistry, member assignment or original model/context
invalidate the previous evidence even when an encoded protein is unchanged.
Complete model ports, catalog dependency closure, localizations and same-recipient
bindings are admitted under the RC3 subset and retained in RC4 evidence. Binary
availability does not establish assembly or expression stoichiometry. The current
closed subset has no numeric expression/stoichiometric-range fields; unsupported
additions reject rather than disappear. Supplied human-cell, co-delivery and
localization premises remain supplied premises.

A private `checked_controlled_material` value exists only after all structural
obligations pass. It carries no behavior, empirical, human-use or therapeutic
export authority. Serialized reports cannot manufacture this value; replay
recomputes and compares the full fresh report. The assessment retains the full
unchanged RC3 admission subreport, structural evidence, actual length accounting,
original bindings/context/resources/budgets and exact request/candidate/invocation
identities. A status of `checked_controlled_material` means only
`exact_supplied_two_member_rna_structure_only`.

## Publication and work ownership

One original work owner covers decoding, construction, fresh admission,
independent reconstruction, report/manifest formatting and final full response
publication. Report byte/node ceilings remain supplied inputs; fixed transport
bounds apply separately. An exhausted invocation cannot publish. The one-shot
native guard checks the exact executable, request ID, operation, result and outer
protocol frame. A failed or consumed guard cannot be reused.

Publication formats only the private checked material value. The artifact is one
ordered FASTA plus one manifest, each independently hashed. The manifest retains
complete originals, candidate, assessment, all region/chemistry records and both
member mappings. The controller and shared source state stay in the single
original authority, never duplicated as per-RNA ownership.

The Python helper calls fresh native publication, stages a deterministic ZIP
containing exactly `program.fasta` and `manifest.json`, verifies staged bytes,
checks cancellation immediately before commit, and atomically publishes one
archive. Existing output survives rejection, exhaustion, cancellation, incomplete
verification and staging failure. Original-input path protection and explicit
replacement rules remain in force. Structural ZIP publication does not grant
therapeutic export.

## Validation boundary

New native suites cover candidate representation, independent literal
construction, structural reconstruction and scoped publication. A separate RC4
hosted campaign exercises the actual Core and Verify binaries, mutation rejection
and atomic publication. Existing RC3, MVP and E1 paths remain isolated and retain
their full supported development census. Local feedback is pure Python, typing
and static/source checks only; native validation runs on hosted CI. A development
run does not replace RC7 integration/cross-platform/installed acceptance or RC8
release qualification.
