# Researcher alpha reference qualification

The first runnable project is an **artificial engineering reference** using the
existing staged component-material profile. A second, state-reading exclusion
case exercises the same public workflow with different source semantics, a
different leader and shifted sequence coordinates. Both preserve their complete
original requests and limits. Neither is a functional reporter, a therapeutic
design, or evidence that a short RNA implements the declared controller.

**A useful, fully specified real researcher project remains open.** The bounded
source review below did not qualify one. This finding concerns the reviewed
candidates; it is not a claim that no suitable public design exists. Shipping a
verified engineering example and qualifying an experimental project are separate
milestones.

## Frozen engineering corpus

[`data/researcher_alpha/`](../data/researcher_alpha/) contains:

| File | Role |
| --- | --- |
| `staged-input.json` | Complete original staged request and limits, frozen from the tracked source declaration packet. |
| `comparison-input.json` | Complete original state-reading case B and limits from the source-bound hosted declaration packet. |
| `expected.json` | Independently declared sequence, FASTA, coordinate, product and finite-domain expectations. It contains no acceptance receipt. |
| `provenance.json` | Exact input/oracle file hashes, upstream declaration provenance and original source hashes. |
| `qualification.json` | Candidate-by-candidate completeness, access and rights status. |
| `negative-controls.json` | Required rejection behavior and the separate incomplete-reference qualification control. These are specifications, not test results. |

Consumers receive these as ordinary data files. Running the public example must
not import fixture generators or read `core/test/data`. Their historical origin
is retained so a reviewer can audit them; generation scripts are not runtime
dependencies.

The first input preserves the two-stage, same-product controller with five
states, two encounter slots and its explicitly supplied finite observation and
feedback domain. The input includes the complete source document, definitions,
component library, composition rule, catalog bindings, provider premises and
budgets. It is not a sequence-only substitute for the therapeutic specification.

The independent structural oracle is deliberately small enough to inspect:

| Case | Declared root assembly | RNA length | CDS interval | Product including stop | Bounded histories / transitions / started prefixes |
| --- | --- | ---: | --- | --- | --- |
| Staged | `CC` followed by `AUGGCUUAAGGAAAA` | 17 | `[2, 11)` | `MA*` | 25 / 86 / 87 |
| Comparison B | `CGC` followed by the same driver root | 18 | `[3, 12)` | `MA*` | 9 / 47 / 48 |

Coordinates are zero-based and half-open. The original declarations specify an
artificial cap identity, an empty modification inventory, and a represented
four-base terminal tail. These are software premises, not chemistry guidance or
known functional parts. The two-base and three-base regions named UTRs are
annotations and do not establish regulatory activity. No sequence was optimized
or adapted for a human cell.

Expected spelling and coordinates were reviewed directly from the separately
authored component root literals in
[`literals.ml`](../core/test/policy_component_support/literals.ml), before running
the new public facade. The codons `AUG`, `GCU`, `UAA` are recorded independently as
`M`, `A`, terminal stop. Complete native producer or verifier output was not used
as the oracle. The comparison input was retained from the existing hosted private
**declaration** emitter, with all four source hashes checked against this
checkout. It was not reconstructed from an exported candidate.

Independent expected bytes do not replace independent semantic verification.
Each new accepted bundle still requires the current original request, fresh
producer-free Verify, every hard requirement, exact source correspondence and
the paired FASTA/manifest publication. Historical passing runs do not validate
the new facade, packaging, or revision. Universal termination, physical controller
realization, expression, delivery, human immune applicability and clinical
admission remain unclaimed.

## Completing real-project qualification

A collaborator can supply a complete existing design without commissioning a
new experiment. An alternative is a complete publicly deposited design with
usable source access and distribution terms. Either must provide:

1. Exact versioned part records, sequence boundaries, joins, product spelling,
   full molecule layout, chemistry and tail declarations.
2. The requested source behavior and explicit compatible implementation,
   provider, resource, observation, feedback and deployment contracts. A CDS
   alone cannot supply those contracts.
3. Independent expected sequence and annotations, plus the original source
   files and provenance. Unknown values remain unknown.
4. A researcher review showing that the specified task and exported bundle are
   useful, followed by a documented clean-install walkthrough.
5. Confirmed terms for any files distributed with the alpha. No project license
   or third-party patent permission is chosen by this qualification record.

The corpus can establish software behavior under its stated premises. It cannot
close these real-project requirements by replacing missing data with artificial
values. The staged and comparison cases also do not establish support for
arbitrary machines, multiple products, modified coding regions or new molecular
mechanisms.
