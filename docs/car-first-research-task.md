# First CAR research task and release contract

Status: implementation in progress; no release or biological acceptance claimed.
This is the first vertical slice in the
[CAR-first roadmap](car-mvp-and-expansion-roadmap-2026-10-10.md).

## User task

A researcher declares one exact CAR protein, a human immune recipient, a
conditional cell-surface localization contract, and a maximum RNA length. The
compiler selects the supplied complete RNA implementation, constructs the
complete nominal molecule, independently verifies correspondence to the original
source and material authority, and exports the exact RNA and a complete manifest.
The researcher can edit the source length constraint, inspect the resulting
requirement decision, retain the project, and independently reopen and check the
same complete source/candidate pair outside the repository.

The first reference candidate is the anti-CD19 RM_61461 / CAR2-OPT4 in current corrected
WO2025096878A9, linked to sequence 151 in the separately retained official WIPO
ST.26 listing. The qualification record distinguishes current publication facts,
independent sequence arithmetic, source-declared chemistry, design premises,
experimental observations and unresolved applicability. Its candidate status
must not be mistaken for completion of the shipped reference pack.

The intended recipient remains a human immune cell engineered in vivo. Published
human T-cell experiments provide supporting reference evidence in their actual
ex-vivo context. They do not establish in-vivo delivery, expression, persistence,
target discrimination, potency, toxicity or clinical benefit.

## Source and executable meaning

The source is an explicit static expression objective. The new versioned profile
uses structural assurance and a `not_applicable` time horizon. It contains no
fabricated cellular action, trigger, controller state or observation. The Python
facade authors immutable data; OCaml source admission and an independent checker
own acceptance. The ordinary policy profile retains its existing syntax and
semantics.

The supported result is conditional encoding and localization: exact supplied
RNA encodes the exact selected complete protein under an explicit nominal
parent-base translation model; the selected component contract supplies the
expression/localization and recipient premises. Sequence correctness does not
prove those premises. Modified bases remain explicit chemistry; their canonical
parent spelling is not an assertion about actual ribosomal behavior.

The first meaningful source edit is a length bound. A bound at or above the exact
complete transcript length can pass; one below it must fail with the original
requirement identity and withhold export. Product, recipient, localization,
implementation, chemistry, region, source-authority and candidate mutations must
also be freshly checked. Unsupported dynamic requirements stay unsupported.

## Complete nominal handoff

The artifact must contain one whole RNA sequence, all named regions, complete
protein identity, cap, modified-base inventory, represented tail and terminal
chemistry. Published sequence and chemistry facts are separately attributed.
Any design-selected end chemistry is explicitly a design premise; it must not
be presented as a measured property or exact physical reproduction of a
published batch. Unknown physical batch properties stay unknown.

The first reference uses published part boundaries, not heuristics such as the
maximal terminal A-run or the first observed stop codon. Independent source
qualification must reconcile every emitted base, protein identity, chemistry
premise, declared coordinate conversion and complete input digest.

## Required product exits

1. Qualified current public-source pack with complete original inputs and an
   explicit evidence/applicability inventory; source retrieval is reproducible.
2. Typed source, admitted domain value, deterministic untrusted construction and
   independent fresh checking are connected by one supported public operation.
3. The installed starter supports authoring, compilation, requirement edits,
   inspection, paired export, fresh verification and reopening without a checkout.
4. Positive and negative controls cover original-source edits, changed authority,
   candidate/manifest tampering, missing evidence, resource exhaustion and
   independent rejection. Mathematical controls never count as wet-lab evidence.
5. Exact-source development, integration/installed acceptance and fresh main
   validation pass before versioned installable assets and the quickstart ship.

A source inspection helper, successful mock, documentation checkpoint, structural
leaf result or historical CI result does not close these exits. The earlier
milestone 1 run is preserved independently; this CAR feature has its own fresh
validation and release identity.

## Expansion boundary

After this complete chain ships, choose the second use case based on a concrete
new user task and available complete material contracts. A second CAR reference
can exercise real implementation choice before adding temporal behavior,
multiple interacting RNAs or a different therapeutic product. Expansion must
reuse the source/contract/material/evidence boundaries established here.
