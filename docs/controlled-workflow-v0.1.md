# Joined controlled researcher workflow v0.1

RC6 connects the artificial two-RNA material profile and reversible activity
profile to the public researcher workflow. It adds ResearchProject v0.3 without
changing the v0.1 component or v0.2 expression project schemas. Implementation
and validation status is recorded in `controlled-composition-progress.md`.

## Complete authority and limits

The original `policy_controlled_workflow_request.v0.1` contains exactly
`schema_version`, `behavior_request` and `limits`. The behavior request retains
the complete RC5 original, including the source program, actual mechanism,
operating domain, supplied RNA authority, catalog, assembly, deployment context,
resources, budgets and independently supplied readout evidence. No saved report
is original authority.

The explicit limits object contains its version, complete original budgets,
domain limits, horizon, intervention cutoff and resources. These are an exact
projection of the original request, checked both in the inert Python boundary
and in the native decoder. They are not a second independently adjustable source
of truth. All project metadata, source records and assumptions must equal the
complete native-bound source project context.

## Fresh native join

`compile-policy-controlled-workflow` is available only in Core. Core proposes
both child candidates and then calls the independent joined checker. Verify
offers `check`, `replay` and `export-policy-controlled-workflow`; it has no
producer dependency. The joined candidate retains both complete children and
the complete joined request fingerprint.

The joined checker freshly checks each child against the same original: the
material checker receives the complete material original and the behavior
checker receives the complete behavior request. Both must yield private native
accepted capabilities before a new private joined capability exists. The full
child reports retain their historical scopes. A report label, candidate hash,
or prior independent PASS cannot create that capability.

One original cumulative work budget owns request decoding, candidate generation
or decoding, both fresh checks, report formation, paired formatting and the
actual complete response frame. The publication guard is consumed even when it
rejects. Each historical child retains its finite domain and output ceilings.
The joined outcome preserves failure, unknown and unsupported states; only two
accepted children permit export.

## Paired publication and independent reopen

`ResearchProject.compile` calls Core and then freshly exports through Verify.
The paired artifact is a single atomic stored ZIP with exactly `program.fasta`
and `manifest.json`. The manifest retains the complete joined original, explicit
limits, both candidates, both full assessments, project context, member order,
complete molecule records and fingerprints. RNA bytes are formatted only from
the fresh material capability contained in the joined capability.

`ResearchProject.verify_bundle` requires an independently supplied project. It
does not recover authority from the bundle. It compares the complete original
and every limit before calling Verify, freshly rechecks both children, and
compares every FASTA and canonical manifest byte. It also checks that the input
archive has not changed during verification. Altering source records, an
assumption, the readout schedule or a requested limit invalidates the old pair.

## Editable artificial program

The typed request exposes RNA size ceilings, five source response deadlines,
horizon with explicit evidence/domain inputs, and complete supplied material
authority. These operations preserve the actual mechanism. Shortening a
deadline never accelerates the mechanism; increasing a horizon never invents
new observations; choosing material never optimizes or fills missing sequence.
Native checking determines the resulting outcome.

The endpoint is sampled `background` or `active` activity. Two supplied products
and controller availability are dependencies under explicit same-cell and
deployment assumptions. The artificial MA/MG products and tiny complete RNAs
exercise software only. Joined acceptance means exact supplied RNA structure
plus conditional behavior over the complete declared finite domain. Empirical
function and human use remain unassessed; therapeutic export remains withheld.

## Validation boundary

RC6 requires an installed outside-checkout public workflow, independent original
inputs, accepted and rejected edits, and an unchanged Verify-only consumer.
Record automated timing separately from human usability. Local feedback and a
hosted development run are not the later RC7 cross-platform release acceptance
or RC8 integration and actual-main validation.
