# Complete researcher-alpha release artifact audit v1

Select `--profile complete-researcher-alpha-release-v1` explicitly. This additive
profile preserves both historical profiles and their classifications. It extends
the committed component auditor with the current complete native census,
four-runtime staged and public researcher workflows, and the candidate starter.
It never builds, executes Core/Verify, discovers tests, downloads evidence, or
publishes a release. The existing authenticated identity, bounded archive,
unit-accounting, and owner acceptance protocol remains mandatory.

## Exact scope

The current workflow expands to **74 physical jobs**, not 67. The number 67 is
the direct-core command-group count. All 59 ordinary receipts, 14 unit artifacts,
102 downloaded ZIPs, 128 required artifact metadata entries, and 173 permitted
artifact names retain their previous classification. All 17 legacy installed
campaigns per runtime, 20 installed-group receipts, six architecture/policy

the four legacy assembled artifacts avoids downloading the same 20 group ZIPs
again; their original nested evidence and independent metadata remain checked.

The new native plan requires 171 suites, 174 executable entries (including Core,
Verify, and the independent original-declaration emitter), and 26 fixtures per
platform. Every suite's exact arguments, return code, log, and identity remain
mandatory. Both emitter executable byte pins are rehashed in the native bundles
and compared with the original-declaration provenance. No emitter is run locally.

The four owned-wheel slots preserve all component and producer-free consumer
checks and additionally require all 16 staged and 20 researcher observations per
slot, complete retained native protocol results, exact caller originals, installed
package and binary ownership, default owned resolver evidence, independently
expected RNA/regions/domain values, and negative controls. Incomplete real
reference metadata must remain unqualified. Biological behavior is unassessed.

The complete v0.4 comparison is reconstructed from those retained inputs. The
starter is then checked independently: exactly 21 copied files and one canonical
manifest, including three already checked wheels, the comparison and candidate,
the comparison-pinned child receipt, two project JSONs, two paired ZIPs, the public
example, four documents, and six original asset JSONs. Extra files, substituted
child receipts, changed source bytes, changed wheels, altered manifest fields,
or broadened acceptance claims fail.

## Run protocol

Acquire and independently authenticate the current PR source H, base B, tested
merge C, equal H/C trees, run/attempt, suite, and complete paginated job/artifact
records using the existing identity schemas. Preserve the exact raw records and
reviewed caller pins. Use the same CLI as the earlier auditor, selecting this
profile for both commands:

```sh
python -B tools/release_audit.py prepare \
  --profile complete-researcher-alpha-release-v1 \
  --tool-revision TOOL_COMMIT --source-root /absolute/clean-source \
  --authority /absolute/evidence/authority.json --authority-sha256 AUTHORITY_SHA \
  --packet /absolute/evidence/packet.json --packet-sha256 PACKET_SHA \
  --output /absolute/evidence/plan.json
```

After all 74 jobs and the suite complete successfully, refresh the authenticated
API packet and acquire the 102 required archives with their exact API hashes,
sizes, names, and run identity. `check` requires the independently pinned prepared
plan plus `--jobs`, `--artifacts`, `--archive-paths`, and `--plan-sha256`. All
original transfer, compressed/expanded/member, and extraction limits apply.
Current physical-job acceptance requires attempt 1; retry support must be
reviewed explicitly rather than relabeling preserved earlier jobs.

Run pure checks against their corresponding source snapshots in separate Python
processes: legacy policy-body tests use the legacy source, component tests use
the component source, and new tests set `BIOCOMPILER_RESEARCHER_SOURCE_ROOT` to
the current complete researcher source. `BIOCOMPILER_AUDIT_SOURCE_ROOT` supplies
the original source for historical policy/component tests. This prevents Python's
module cache from combining different historical source authorities.

A passing audit reports `pass_for_stated_scope`. Final owner acceptance still
requires the complete hosted gate, an exact-head normal merge with parent/tree
proof, and a fresh complete actual-main run and audit. The starter continues to
say `installed_candidate` and `pending_overall_and_actual_main_gates`; an auditor
must not rewrite those producer claims after the fact.
