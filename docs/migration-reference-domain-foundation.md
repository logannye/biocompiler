# Reference construction and molecular emission in OCaml

This batch supplies the native domain, producer and independent checker foundation
for the existing exact-reference workflow. It does not route a public workflow,
change the production default or complete LM-CUTOFF-1. The historical reference
utilities remain shared infrastructure. Their DNA fixtures do not add a new
therapeutic product target or establish biological function.

The [source checkpoint](../protocol/migration-reference-domain-foundation-checkpoint.json)
pins the implemented source, frozen expected corpus and completed local controls.
Its pending native status is deliberate.

The modern circuit-construction and molecule schemas already ported to OCaml
cannot replace these older public types. The reference workflow has its own
single-CDS layout authority, complete reference manifests, registry locks,
translation policies, feature-status declarations and scoped evidence. Preserving
those distinctions is necessary for the original public manager and build objects.

## Implemented boundaries

`Reference_manifest`, `Reference_components`, `Reference_construct` and
`Reference_molecular` define abstract validated types and controlled constructors
for 23 original domain kinds. They preserve complete fields, explicit DNA/RNA/
protein distinctions, source identities, exact coordinates, rich unsupported
layout declarations and the original UTF-8 or ASCII fingerprint profile of each
type. Reference normalization and CDS translation remain explicit operations.
Their results do not promote reference status or delivered-context claims.

`Reference_construct_producer` prepares the original single-CDS request and
generates its declared layout. `Reference_sequence_emitter` first obtains a fresh
construct assessment from independent request, registry and manifest authority,
then emits the selected record's own nucleotide sequence. It preserves the
original encoding, translation and evidence policies, unknown features and
source fingerprints. It does not perform implicit DNA/RNA conversion or optimize
the sequence.

`Reference_construct_check` and `Reference_molecular_check` reconstruct their
assessments separately from those producers. Their private support module is
confined to the checker library. Typed evidence retains full diagnostics,
dependency identities, outcomes and freshness/replay behavior. The dependency
gate continues to prohibit checker imports of compiler or emitter libraries.
Shared domain decoding and canonicalization remain a common trusted base; their
agreement is not independent evidence of biological correctness.

The new bounded legacy JSON profile supplies original duplicate-key and explicit
nonfinite-constant rejection order for captured raw-text calls. Existing strict
JSON parsing retains its original behavior. Legacy UTF-8 pretty output and the
existing ASCII identity profile stay distinct. This batch does not claim every
CPython malformed-text diagnostic: general syntax-error wording and overflowing
exponent precedence still need an explicit compatibility decision and tests
before claiming unrestricted raw-text frontend parity.

## Resource limits

Producer invocations share one work ancestor with nested independent checking.
Input and output reservations are cumulative; constructors and serializers
charge traversal before publication. Caller limits may reduce the fixed profile,
never enlarge it. Overflow, cycles, exhausted ancestors and failed reservations
cannot result in a published artifact.

Emission checks its entire actual input inventory against the producer's reduced
input-node allowance before entering the checker. The checker additionally keeps
its existing stricter per-document input ceiling. Applicable byte, report-node,
work and item reductions propagate into nested checking; the producer output
limit is not merely a final-artifact check. Focused tests exercise actual
preparation, generation and emission at exact and one-short work boundaries,
reduced inner report limits, cumulative reservations and cyclic native values.

## Independent expected data and validation

The frozen capture executes 72 unchanged original Python tests and retains
22,584 complete observations from 43 operations. Its 4,000 content-addressed
documents contain 34,923,274 bytes. Inputs, successful values, fingerprints,
layout fingerprints, JSON spellings and 4,292 original exceptions are retained
whole. The corpus includes 42 additional emitter calls using original mutated
construct inputs; the emitter's expected result is freshly captured from the
original implementation, never inferred from a checker label.

All eight capture/integrity controls pass on Python 3.11.15 and 3.14.6, including
a fresh byte-for-byte recapture. These are Python baseline results. They are not
native parity evidence.

Five hosted native suites cover legacy JSON, domain identities, independent
checking, producer budgets and every corpus observation. The runner rejects
unknown operations and distinguishes typed argument-import failure from the
expected operation error. It compares complete output values and serialized
representations; no captured result is imported as accepted native state.

The existing 36-job CI topology now contains 107 native suites on both supported
platforms. All 43 affected Python CI/boundary controls pass on each local Python
version, and the final static dependency graph passes. Native compilation,
execution and complete hosted acceptance remain pending. No native build or
native executable was run locally.

## Remaining integration

manager and public typed views. Preserve actual generator/emitter overrides,
public registration interception, dependency-write order, callable identity,
partial failure state and original return-object identities. The original
reference manager corpus and full workflow families remain authoritative.

Canonical reference packaging and fresh export acceptance remain separate work.
So do the other supported molecular, intent-candidate, executable-RNA and Studio
entry points, prebuilt distributions, fresh installations and default cutover.
An accepted exact-CDS artifact never discharges empirical or human-use obligations.
