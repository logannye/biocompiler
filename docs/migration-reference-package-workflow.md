# Native reference package construction and current reconstruction

The reference package library now constructs a complete archive from actual
OCaml Construct/Molecular pipeline capabilities. Immutable snapshots validate the
reviewed reference manifest and every retained source/review byte. A separate
producer library derives the reference selection, component registry, lock and
construction request. This preserves the historical reference utility; it adds
no product target or biological claim.

Package construction retains the original load/collect/run sequence, both
candidate reads, accepted manager records, fresh composition/construct checks,
sequence export, complete members and late SDK/tool-version lookups. The archive
uses the existing canonical manifest and stored-ZIP primitives. Its final manager
record and result come from the actual live build. Serialized PASS records do not
initialize or authorize the workflow.

An abstract checked-export value binds the owner, request, construct, molecular
artifact, registry, ordered manifests and FASTA width to a fresh independent
molecular check. Encoding an artifact alone cannot create this value. Existing
standalone export accounting remains unchanged.

Current package reconstruction requires an independently trusted request or build
fingerprint before reading imported content. It reconstructs a new native build
from the retained authority and compares complete current manifest/archive bytes.
Changed tool versions, stale authority and callback failures cannot inherit an
imported acceptance result. Mapping equality meters each actual key comparison;
the final canonical fingerprint still binds exact representation.

Reconstruction deliberately belongs to the producer library. It is the historical
rebuild operation, not the separate producer-free verifier. Static link rules
reject any path from a checker or standalone verifier into that library. This
checkpoint does not yet expose package operations through either executable.

One explicit package owner applies a 512 MiB cumulative persistent-data allowance
across snapshots, manager records, pipeline builds, export, members and archives.
Descendant work scopes inherit that owner; they cannot replace it or refund
charges. Actual persistent checker outputs are measured before attachment. Each
checker's existing input, output, item and work ceilings continue to bound its
temporary work; the persistent allowance is not a process-RSS bound. Original
work profiles without a retention owner keep their prior charging behavior.
Retention failures, swallowed reentrant failures and work exhaustion close the
owned lifetime before later publication can proceed.

The frozen Python 3.11 and 3.14 witnesses retain 17 complete input/constructor
observations and eight complete package observations. The package cases cover
DNA/RNA, width 1/80/10000, run metadata, changed current SDK/tool versions and an
unsupported layout. Both runtime profiles are byte-identical for these cases.
The native suites compare whole documents and archive bytes, then exercise exact
and one-short resource allowances, authority changes, owner substitution and
fresh reconstruction. Original expected bytes remain unchanged.

The three added suites bring required native coverage to 117 suites on each
hosted platform. Python controls, dependency checks and CI wiring checks pass
locally; they do not validate native execution. Complete hosted tests, public
transport, current-module adapters, independent package verification, atomic
publication and installed package/export campaigns remain required. Production
defaults remain Python and all four session cutoff gates remain open.
