# Bounded policy machine networks v0.1

This additive profile realizes networks of interacting controllers through the
existing admitted source language and staged primitive runtime. Each controller
owns its state and retained effect attempts. Independent event observations and
explicitly owned truth stores provide bounded communication. The existing
single-machine, staged, exact and quantitative families retain their meanings.

## Original authority and bounds

The original realization request uses schema
`biocompiler.policy_realization_request.v0.6` and profile
`biocompiler.policy_network_inputs.v0.1`. The binding uses
`biocompiler.policy_implementation_binding.v0.6` and
`biocompiler.policy_network_source_graph.v0.1`. The outer material request uses
`biocompiler.policy_component_material_request.v0.9`, with material and context
profile `biocompiler.policy_network_component_mrna.v0.1`.

The closed family admits one executor, one encounter declaration with exactly
two original encounter slots, one subject, clock and fixed text product. It has
2–4 machines of 2–16 states each, 2–4 truth observation streams with distinct
coherence groups and individual freshness, 0–4 encounter-local truth stores,
1–32 transitions and 1–8 effects. Each machine has a transition. Each effect has
exactly one initiating transition; a transition requests at most one effect.
Independent rules, channels, messages and effect resource-contract semantics
remain outside this family. The existing 64-node composition ceiling and all
codec, work and publication bounds continue to apply.

Stores begin at a known boolean value and have exactly one writing machine.
Other machines may read them. A transition cannot write a store twice. Guards
and assigned truth expressions use literals, observation reads, store reads,
negation, conjunction and disjunction. Triggers are original observation
updates, rising observed expressions, or completed/failed/timed-out feedback for
an effect initiated by the receiving machine. Store-only rising events and
explicit reset predicates are unsupported.

## Python entry points

The existing typed source vocabulary constructs observations, stores, machines,
transitions and effects. Python executes authoring code; these declarations
specify the runtime behavior. No new Python control-flow interpretation is added.

Use `policy.implementation.prepare_request(..., prerequisites=True, network=True)`
for the complete original source, domain, model library and catalog bridges.
Use `policy.component_material.prepare_request(..., instanced=True,
prerequisites=True, network=True)` for selected reusable components, exact input
and resource bindings, context and material authority. These functions snapshot
inputs; only fresh native checking can grant acceptance. Incompatible profile
flags reject. The module-linking facade accepts this complete material request
through its existing child interface.

The independently specified example is generated by
`tools/generate_policy_machine_network_fixture.py` and stored in
`core/test/data/policy_machine_network_v01.json`.

## Atomic transitions and communication

Every machine uses explicit priority arbitration with declared-order ties and
rejected write conflicts. Machines with identical complete arbitration policies
share an arbiter, matching the source interpreter. Each policy orders exactly
all transitions in its group. Distinct policies with their own complete orders
allow independent groups to commit simultaneously. A shared policy deliberately
resolves competition according to its declared order. There is no implicit
fairness, preemption or scheduler contract.

Primitive arbiter lanes follow original transition order filtered to the group;
the declared priority order maps identities onto those lane indices. Machine
writers follow original transition order filtered to that machine. Store
writers follow original assignment order filtered to that store. Independent
checking reconstructs each mapping from the original source.

Guards and assigned values read the precommit snapshot. A same-tick store write
cannot immediately enable a peer transition. A later eligible event observes
the committed value; changing state alone does not wake another controller.
Unknown, missing, stale and conflicting evidence remain explicit. Observation
streams have independent freshness and coherence. They do not implicitly join
into a simultaneous evidence frame.

Retained attempts preserve machine, encounter-slot and generation identity.
Feedback cannot serve as an untyped message to another machine. Encounter reset
clears the slot's machine state, truth stores and retained attempts, and changes
its generation. Other slots remain independent. A late reply for an earlier
attempt cannot complete a newer attempt.

## Components, resource claims and payload

A network lowers into supplied evidence banks, truth registers, machine banks,
transition gates and commits, priority arbiters, and attempt banks. The checked
source-to-input mapping is mandatory when arranging named reusable components.
The component context independently derives demands from the actual checked
graph, complete original domain and record layout. Shared provider pools must
cover the sum of their allocations, including simultaneously active controllers.

A physical capacity declaration is a supplied contract. A logical capacity-one
protocol can be expressed separately with controller-owned busy flags, a shared
priority group, and an explicit safety requirement forbidding both flags at once.
Its bounded safety claim comes from whole-program checking. It does not prove a
physical mutual-exclusion mechanism, delivery or provider capacity in human cells.

Every original hard requirement, complete bounded exploration, source/candidate
preservation, checked component assembly, provider closure, record capacity,
exact material construction and fresh export remains conjunctive. Module-linked
programs retain the existing exact elaboration evidence and undergo these same
whole-program checks. No separate module proof substitutes for them.

Material evidence uses the existing assessment shape with checker implementation
`biocompiler.ocaml.policy_component_material_check.v0.9`; context evidence uses
`biocompiler.ocaml.policy_component_context_check.v0.8`. New service capabilities
are `policy_network_implementation` and `policy_network_material`, with producer
companions. Existing operation names remain unchanged. The exact refinement
relations and their original premises also remain unchanged.

Artificial fixture RNA demonstrates exact software construction under supplied
contracts. Source review, fixture generation and mocked transport tests do not
establish native execution, empirical mechanism function or clinical evidence.
