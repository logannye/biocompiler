Native component adaptation exposes ordered phases through five new operations:

1. `build-result` returns the actual retained synthetic or component build.
2. `prepare-components` performs native adaptation and returns a preparation
   capability plus the ordered dependency declarations.
3. After the actual dependency updates, `component-profile` constructs the
   original completion profile. The facade performs the ordinary registration.
4. `component-registration` constructs the original contract and native producer
   and validator closures. The facade performs ordinary register, run and result
   calls on the same live manager.
5. `finish-components` resolves that actual run record's incarnation and the
   exact result command sequence, performs the original native final checks and
   returns the complete component build.

The shared OCaml pipeline uses these same phase implementations at the original
constructor and mutation points. Logical and host failures preserve prior
successful mutations. No manager is reconstructed from observations, and finish
does not replace the actual result with a newly computed query. Preparation and
result capabilities belong to one live manager and its cumulative lifetime
budget. Fatal protocol failures close authority.

record definition once per channel, then references its actual incarnation. It
still observes the complete current manager state. Definitions must occur in
first-reference order and may not be missing, renamed, duplicated or rebound.
The Python facade and independent receipt checker expand them from their own
checked channel histories. Existing `inspect-ordered` is unchanged. This avoids
repeated large record payloads within the existing cumulative channel allowance;
the resource ceiling is not raised. Adjacent original before-state observations
may share the immediately preceding after-state inspection only when its exact
response is still current and no frame or native activity intervened. Every
original operation retains a fresh after-state inspection.

The original object graph requires several explicit construction origins:

- Parsed candidate node input and requirement tuples, program outputs and required

- Lowering proposals retain the exact actual context input's intent-node inputs

These are finite representation rules, not content interning or authority to
recompute biological meaning. Historical build inspection cannot grant fresh
